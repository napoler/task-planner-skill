# task-planner 结构化状态升级：JSON 权威源 + Python 脚本固化 SOP

## Context

两个会话实测慢到无法用于工作（16h+/10h+）。根因不是任务复杂，而是架构缺陷：
1. **正则抽取脆弱**：`check-vc-nonvacuous.sh`、`check-rvc-coverage.sh`、`check-plan-audit-gate.sh`、`check-evidence-anchor.sh`、`attest-plan.sh`、`check-complete.sh` 用 awk/grep 从半结构化 Markdown 抽 VC 命令、审计结论、需求映射——格式一变就假绿/误伤/漏匹配，critic 在 R1→R9 反复打回（会话1 烧了 6 个 opus critic / 1270 万 token）。
2. **文本编辑易错**：Agent 反复 Edit progress.md / task_plan.md，锚点吞块、SHA 漂移重 attest、l0-lite stub 双门摩擦。
3. **检索靠语义**：没有结构化 tags，只能全文正则/语义搜索。

用户裁决：正则不是最高效策略，改用**固定脚本**把 SOP 固化——结构化数据（JSON 权威）+ Python 脚本增删改查/备份 + tags 检索库，Agent 不直接编辑文件。

## 架构设计

### 1. 权威数据源 `<plan-dir>/plan-state.json`（唯一真相）

单一 JSON 文件承载所有频繁操作字段，schema 版本化、可校验：

```json
{
  "schema_version": 1,
  "task_id": "task-ep36-...", "plan_tier": "standard", "execution_lane": "L1",
  "created_at": "...", "updated_at": "...",
  "requirements": [{"id":"R1","text":"逐字原文","type":"目标|手段","vc":["VC-1"],"tags":["..."]}],
  "goals":        [{"id":"G1","text":"...","vc":["VC-1"],"tags":[]}],
  "vcs":          [{"id":"VC-1","criterion":"...","command":"...","status":"pending|pass|fail","evidence":"...","tags":[]}],
  "phases":       [{"id":"P1","status":"pending|in_progress|complete","s_units":[...],"v_checks":["V-1.1"],"tags":[]}],
  "findings":     [{"id":"F1","text":"...","source":"...","tags":[]}],
  "audits":       [{"round":1,"verdict":"APPROVED|REJECTED","by":"critic","counts":{"C":0,"I":0,"W":3},"at":"..."}],
  "delegations":  [...],
  "tags": ["全局标签"]
}
```

### 2. Python CLI `<skill>/scripts/planctl.py`（SOP 固化载体）

子命令（按 id 精确操作，取代正则/文本编辑）：

| 命令组 | 子命令 | 作用 |
|---|---|---|
| 生命周期 | `init / get / status / validate` | 建/读/查状态/schema 校验（fail-closed） |
| 增删改查 | `set / add / update / delete` | 按条目 id 精确修改 requirements/vcs/phases/findings/goals |
| 状态流转 | `phase-done / vc-pass / vc-fail / audit-add` | Phase/VC/审计状态翻转，自动带时间戳 |
| tags | `tag-add / tag-search` | 写入时打标签；按标签精确检索（倒排索引） |
| 安全 | `render / backup / restore / history` | 生成 MD 视图 / 原子写入前备份 / 按需恢复 |

**写入安全（用户明确要求）**：
- 原子写：临时文件 → fsync → `os.replace()`，杜绝半写
- 自动备份：每次写前把旧版存 `<plan-dir>/.history/plan-state-<ts>-<seq>.json`，保留最近 N 版，`restore`/`history` 随时找回
- schema 校验：写入前后校验，`jsonschema`（或手写等价）不通过即拒绝

### 3. tags 检索库

- 每个条目（requirement/vc/phase/finding）写入时可带 `tags`
- workspace 级倒排索引 `<workspace>/plans/.tags-index.json`：`{"tag": ["<task_id>#<entry_id>", ...]}`
- `planctl.py tag-search --tag xxx` 走索引 O(1) 命中，取代全文正则/语义猜测

### 4. MD 视图（保留可读性，脚本生成，Agent 不写）

`planctl.py render` 从 JSON 生成 `task_plan.md` / `progress.md` / `verification.md` / `findings.md`（沿用现有文件名，兼容 hook 与人工审阅）。**逐字需求日志 user-session-log.md、knowledge-brief.md 保留 Markdown 不迁**（append-only 自然语言，非频繁结构化操作）。

### 5. 迁移映射（全量频繁面）

| 原 Markdown 字段 | → JSON 路径 |
|---|---|
| task_plan.md: R 行 / R→VC 映射 / Goal / VC 表 / S-unit / Phase 状态 / 委派统计 | requirements / goals / vcs / phases / delegations |
| progress.md: Phase 状态翻转 / findings 回填 / 审计留痕 [plan-audit-RN] / Error Log | phases[].status / findings / audits |
| verification.md: VC 勾选 / Evidence / 交叉验证记录 | vcs[].status / vcs[].evidence |

### 6. 机器门改造（消除正则抽取）

| 现脚本 | 改为 |
|---|---|
| `check-vc-nonvacuous.sh` | `planctl.py check vc-nonvacuous`（读 JSON vcs[].command，保留静态真空判定逻辑，用 Python 实现） |
| `check-rvc-coverage.sh` | `planctl.py check rvc`（JSON requirements↔vcs 双向覆盖） |
| `check-plan-audit-gate.sh` | `planctl.py check audit`（读 JSON audits，形态硬门保留） |
| `check-evidence-anchor.sh` | `planctl.py check evidence`（JSON evidence 路径 + 文件头校验） |
| `attest-plan.sh` / `check-complete.sh` 的 VC/门段 | 改调上述 `planctl.py check ...`；attest hash 对象改为 plan-state.json（权威源） |
| `init-session.sh` | init 时生成 plan-state.json（从 schema 模板），MD 视图由 render 产出 |

### 7. SOP 固化（Agent 不直接编辑）

`SKILL.md` 增加"结构化状态操作 SOP"硬条款：所有 todo/Phase/VC/findings/审计状态变更**必须**走 `planctl.py <subcommand>`，禁止 Agent 直接 Edit/Write `plan-state.json` 及脚本生成的 MD 视图；违反=流程无效。旧正则脚本保留为兼容 shim（内部转调 planctl.py），过渡期不破坏存量计划。

## 边界与风险

- **脚本语言**：用户显式要求 Python，优先于默认 Bun+TS 偏好；仓库已有 Python 先例 `plan-resume/scripts/score-plans.py`
- **兼容存量计划**：旧正则脚本保留 shim，存量 MD 计划不强制立即迁移；新机制随新计划生效
- **hash 变更影响**：attest hash 对象从 task_plan.md 改为 plan-state.json 会影响存量计划 attestation → 过渡期双写兼容，迁移窗口后再单一化
- **不迁内容**：user-session-log.md（逐字 append-only）、knowledge-brief.md（自然语言知识）保留 Markdown
- **worktree 合并冲突**：若并行会话改动同批文件，按宪法 §十一冲突延后到合并期处理，不在执行期打断
