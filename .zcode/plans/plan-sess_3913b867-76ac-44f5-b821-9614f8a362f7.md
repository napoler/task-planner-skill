# 检索排除清单机制（task-retrieval-exclude-20261123）

## Context（为什么做）

用户反馈：当前检索机制**没有做排除**，导致无用临时文件/资料文件被读进会话、冗余信息淹没上下文，执行一个「改几个提示词」的任务耗时十几小时。用户要的机制是：
1. 项目可维护一份**排除文档**，逐条注明「什么情况可排除 / 什么情况不排除」；
2. **每次检索前先读该文档**，按条件做排除；
3. 以后发现新的可排除目录，继续往该文档维护。

已有雏形：Rule 100.6（trash/ 检索排除）是唯一现成的检索排除规则，但只对 trash/ 硬编码，缺少通用、可维护、条件化的载体。本方案把它泛化为「项目级排除清单 + 一条检索前必读规则」。

**用户三项定案**：范围=skill 规则 + 当前项目清单；初始排除项=仅 `trash/`（以后再维护）；强制程度=纯文本规则条款（不加 hook/脚本）。

## 推荐方案

### A. 项目根新建排除清单文档 `RETRIEVAL_EXCLUDE.md`

放在 `/mnt/data/dev/task-planner-skill/RETRIEVAL_EXCLUDE.md`（执行细节自主裁决：英文名便于 grep/识别，与 `.gitignore` 呼应）。核心是**条件化表格**——每条排除项必须同时写明两种场景（用户强调的重点）：

```markdown
# 检索排除清单
> 用途：任何检索动作前先读本清单，逐条按「可排除场景/必须纳入场景」判断。
> 维护：发现某目录对某类工作无意义即追加一行，须写明两种场景+理由。
> 关联：Rule 112；Rule 100.6（首个条目来源）。

| 路径/模式 | 说明 | ✅ 可排除场景 | ❌ 必须纳入场景 | 依据 |
|---|---|---|---|---|
| `trash/` | 判废数据/落选稿垃圾桶 | 后期正常检索/数据回找/素材选型/Explore·grep·glob·ls 扫描 | 确认误删/误判废需找回（找回后原位登记） | Rule 100.6④ |

## 维护日志（日期 | 变更 | 理由）
```

初始只放 `trash/`；`.history/`、`.fix_*.py`、资料目录等**暂不纳入**，仅作候选（用户未选，遵循范围最小化 YAGNI）。

### B. 新增顶层 Rule 112「检索排除清单纪律」

落点：`skills/task-planner/references/critical-rules.md`，Rule 111 之后（约 :249 追加）。选顶层而非塞进 Rule 75（网络调研域）或 Rule 100（临时目录域）的理由：本规则跨本地检索/网络调研/执行回找多域、需每轮可见，顶层最醒目；且是 100.6 的通用化，**100.6 原文不改**（Rule 36.5 纯增量）。

子条设计：
- **112.1 清单载体**：项目根 `RETRIEVAL_EXCLUDE.md`，表格五列；每条必须写两种场景+理由，禁只写「排除 X」。
- **112.2 检索前读清单（P0 触发）**：任何检索动作（Explore/Grep/Glob/ls 目录扫描/Read 目录列举/素材选型/数据回找）前，先确认本会话已读当前项目清单（首次检索读一次，后续复用）；清单不存在=无额外排除，无需新建。
- **112.3 条件排除判定（P0）**：命中「可排除场景」→注入排除参数（grep `--exclude-dir` / Glob ignore / Explore prompt 注明 / ls 过滤）；命中「必须纳入场景」→正常读取；**都不命中→默认不排除**（保守，宁可多读不漏关键）。
- **112.4 子代理传播**：派发 Explore/general-researcher 时，prompt 携带清单排除路径列表（对齐 22.4f）。
- **112.5 与既有规则关系**：100.6③ 的通用化载体，trash 为清单首条；与 105.1（枚举面排除 trash）、62.4b（公共上下文一次读取）互补。
- **112.6 机制**：L0-T 文本锚（对齐 100.5/111），判定面=LLM 行为+文本锚，零新脚本、零新 config 键、零 hook（用户已选纯文本；宪法 §二文本优先铁律）。

### C. SKILL.md 加指针（只加摘要，不碰数字索引）

在 `skills/task-planner/SKILL.md` 的 Critical Rules 摘要区（Rule 111 两条附近，约 :94/:201）加 1 条 Rule 112 指针。**不修改 :312 的 "Rules 1-110/核心 15 条" 索引**——该索引已被证明是近似索引（111 落地未同步），改它 Cascades 到 selftest 计数断言，超出用户授权的纯文本范围。
