# 模板检索/管理技能脚本 —— 清单化模板匹配并固化进 SOP

## Context（为什么）

用户诉求原话要点：新增一个模板检索/管理脚本；任务初期调用它拿到「当前项目已有模板 + 用户级别模板」清单（每项含模板名/简介/适配场景/功能），据此匹配适配当前任务的模板，让匹配流程化并写入 SOP；脚本还要支持模板添加/克隆/基于模板派生；所有用法与示例注入 SKILL.md 确保后续可调用。

三路 Explore 取证结论：
- **无 SQL/DB 实现**：全仓无 sqlite3/.db，现状是 JSON 权威源 + `.tags-index.json` 倒排索引（planctl.py:46）。用户「SQL」最可能是「索引/检索」口述。
- **`init-session.sh --list`（:21-53）已有枚举但够用度低**：仅人读文本、只扫 CWD 向上项目目录 + 内置 variant，无跨安装位、无 JSON、无场景/功能字段。
- **元数据不齐**：31 个 variant `template_type` 齐全，但简介/场景/功能是格式不一的注释散文（video `video-type.md:5` 单行、code-edit `code-edit-type.md:2-4` 三行标签），机器读不稳。
- **可复用面充足**：项目模板发现 `init-session.sh:64-79`、复制优先级 `:82-97`、动态白名单 `check-template-type.sh:15-18`、planctl `emit/PlanctlError/atomic_write`、幂等复制 `install-companion.sh:84-149`、lineage 注入 `inject-template-lineage.sh`、spec 扫描 `scan-template-spec.sh`。
- **SKILL.md 注入点**：`:45`（模板优先级行，初始化机械子动作内）为主承载；plan-template-kit 是纯知识层，只做交叉指针。

澄清问题未获答复 → 按推荐项自主决策登记（Decisions Made）：
- **D1 查询方式** = 文件扫描 + 可选 JSON 清单缓存，不引入 SQLite（零新依赖、无索引一致性成本、贴合 JSON 权威源）。
- **D2 元数据载体** = 模板头统一 `template_meta` 注释块（元数据随模板走不漂移；改动仅 `skills/templates/`，属改进 skill 范围，不碰 `plans/` 存量计划）。

### W2 新脚本 `skills/task-planner/scripts/template-catalog.sh`
风格对齐 `check-template-type.sh` / `planctl.py`（shebang + 日期/任务标签 + Usage + 输出契约 + exit 码，`set -euo pipefail`）。

作用域枚举（复用 `init-session.sh:64-79` 发现逻辑）：
1. **project**：CWD 向上最近的 `.claude/plan-templates` / `.zcode/plan-templates` 下 `*-type.md`（scope=project）。
2. **user-global**：`$HOME/.claude/plan-templates` / `$HOME/.zcode/plan-templates`（若存在；当前 init-session.sh 不扫，本脚本补上，scope=user-global）。
3. **builtin/用户安装位**：当前脚本安装位 `<skill-install>/templates/`（`variant/*-type.md` + base）；`--include-installs` 可枚举 `~/.zcode|agents|claude|cursor/skills/task-planner/templates/`（scope=user-install）。
- 去重（同名 type 优先级 project > user-global > builtin），标注 `default`（项目 default > `TASK_TEMPLATE_DEFAULT` > general）与 `valid`（白名单派生同 `check-template-type.sh:15-18`）。

子命令：
- `list [--json] [--scope builtin|project|user|all] [--query <关键词>] [--recommend <任务描述>] [--include-installs]`：每项输出 name/type/scope/summary/scenarios/features/path/default/valid；`--json` 稳定 schema 供机器消费；`--query`/`--recommend` 按关键词在 name/summary/scenarios/features 上过滤/排序，辅助模型匹配（**不替模型决策**）。
- `add <name> [--from <type|path>]`：用户「添加或克隆」语义合并（原话「添加或者克隆…就可以，就是克隆嘛」）——即克隆/新建骨架的统一入口。
- `clone --from <type|path> --to <name> [--scope project|user-global] [--dry-run]`：从源模板复制到目标作用域（默认项目级 `.zcode/plan-templates/`），改写 type 与 meta 骨架，注入 lineage parent（复用 `inject-template-lineage.sh` 模式）；幂等 + 备份 + 同名拒锁 + dry-run（复用 `install-companion.sh:84-149` 模式）。
- `derive --from <type|path> --to <name> [--prune <逗号分隔段名>] [--scope …] [--dry-run]`：基于 clone 按 `--prune` 裁剪领域段并登记 pruned 清单（对齐 Rule 34.5 派生登记），产出新 variant 骨架待人工填。
- 只读 `list` 零写入；写操作仅落目标作用域目录，禁未显式 `--force` 覆盖已存在模板。
