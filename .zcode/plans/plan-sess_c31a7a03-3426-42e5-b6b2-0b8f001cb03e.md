## 改动（4 项，均落到我亲自读过的函数行号）

**修1 · planctl.py 写接口容错**（治 schema 反复试探 6-7 次）
`scripts/planctl.py`：`normalize_entry:671-691`、`_validate_entry:399-565`
- 根因：`known`/`required` 对每个 section 零容错（如 :483 research 只认 `claim`、:486 decisions 只认 `rationale`、:472 errors.attempt 要 int、:447-451 audits.counts 只收 C/I/W），而 `normalize_entry` 不补 id/round/timestamp、无字段别名。会话里写错一次报"未知字段 X"，不给合法示例，只能盲试。
- 改：`normalize_entry` 加字段别名归一（source→rationale、conclusion→source、question→claim 等，仅在该 section 合法字段集内）+ 自动补 id/round/timestamp/at + counts 把 N 等非 C/I/W 键移入 tags；校验错误附该段 required 清单和一条合法 JSON 示例。

**修2 · attest 锁权威源**（治 render/attest 锁失效、"四步"返工）
`scripts/attest-plan.sh:649,657-664`、`scripts/planctl.py:1623-1631`
- 根因：:649 `hash=sha256sum "$plan_file"` 锁的是 task_plan.md（render 每次全量覆盖的派生视图），render 后必失配。
- 改：attestation 增 `state_sha256`（锁 plan-state.json，render 不动它），verify 以此为准；plan_sha256 降为信息字段。删掉 SKILL.md:356-375"执行期只写 JSON 不 render"的绕行条款，恢复正常 render。

**修3 · 审计无进展止损**（治 5 轮审计不触发上抛）
`scripts/planctl.py:222-246` audit_no_progress
- 根因：只判"最近 3 连续 REJECTED 的开放 C/I key 集完全相同"；本次 2C/12I→1C/6I→0C/3I→0C/1I→0C/0I 每轮 key 变，判定永不命中。
- 改：增第二触发——累计 REJECTED≥4 且末轮非 APPROVED → 上抛（key 每轮换但同一计划反复打回=真无进展），reason 与 NO_PROGRESS_STREAK_3 并列；末轮 APPROVED 仍不误伤。

**修4 · auto-tier 默认开启**（治简单任务误判 L1 走全套）
`scripts/init-session.sh:581-690,748-890`、`scripts/task-plan-init.cjs:39`
- 根因：auto-tier 要 `TASK_AUTO_TIER=1` opt-in；关键词只提示不降档 → "加位置信息"进 L1 → 全套审计+委派率门。
- 改：不改任何门；auto-tier 缺省 on（改 opt-out），scope 全 .md/.txt ∧ 无新脚本/config/hook ∧ 单模块 → 自动 mini/L0-T，按既有档位规则走。
