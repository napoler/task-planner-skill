# error-fix-prompt-forge · 排查结果→修正提示词锻造

闭环: 已定位根因的排查结果包 → 五步锻造(校验→抽取→缺口→渲染→自检) → 自包含 fix-prompt.md + QC-FP 自检表 + 三态结论,可直接派发子代理执行。

**Goal**: 输入 = 已定位根因的排查结果包;输出三项:

- **fix-prompt.md**: 自包含修正任务书(根因 + 证据锚 + 范围 + 禁改区 + ≥1 机器可检查验收 + 回滚)
- **QC-FP 自检表**: 逐条 PASS/FAIL + 证据(机检项必附命令输出)
- **三态结论**: READY / PARTIAL / BLOCKED(定义见「输出合约」)

## 触发条件

- 用户完成错误排查/调研,要把排查结果转化为修正提示词/修正任务书(fix prompt / fix task brief)
- 排查结果已含根因结论(root cause),后续执行走子代理派发
- 跨会话交接: 上会话已排查,本会话需产出可派发任务书

不触发:
- 根因未定位(root cause not identified)→ 先 debugger / systematic-debugging 排查,再进本 skill
- 一次性小修(≤3 行单文件)且无需派发 → 直接做,勿套任务书
- 通用提示词润色/工程化 → prompt-master / prompt-corrector
- 代码质量/安全/测试审查 → review 族;完成前验证 → verification-before-completion

## 执行前输入契约

| 输入 | 要求 | 缺省 |
|------|------|------|
| 症状 + 影响面 | 必填 | 缺失 → 与用户协商,协商不成 → 不启动 |
| 复现路径(命令/步骤) | 必填;不可复现须登记原因 | 同上 |
| 根因结论 | 必填且已定位 | 未定位 → BLOCKED,退回排查 |
| 证据锚 ≥1(file:line 或命令输出) | 必填 | 缺失 → 只能入「未验证假设区」显式标注 |
| 已尝试方案(防重复试错) | 必填 | 缺失 → 与用户协商 |
| 约束禁改区 | 可选 | 无 |

契约规则(fail-closed): 缺任一必填项 → STOP,与用户协商;协商不成 → 不启动;根因未定位 = BLOCKED,退回排查不出稿。

## 执行流程(五步)

- [ ] [M] **Step 0 输入校验**: 逐项核契约;根因结论无证据锚 → 只可入「未验证假设区」并显式标注,禁入提示词主体;根因未定位 → BLOCKED 不出稿
- [ ] [M] **Step 1 结构化抽取**: 排查结果映射槽位表: 问题陈述 / 根因+证据 / 影响面 / 复现 / 禁改区 / 验证判据 / 回滚 / 参考材料
- [ ] [A] **Step 2 缺口分析**: 逐槽位问「执行体拿到这个能干活吗」;阻断级缺口(缺机器可检查验收/缺复现路径/缺范围定义) → 禁出稿 + 列缺口清单交用户补;非阻断 → 登记「未验证假设区」
  **可选思路**:
  1. 思路 A: 逐槽位清单式核对——按槽位表逐项打勾「可干活/有缺口」,产出可追溯的缺口清单(适用场景: 槽位少、结构清晰、需留痕可追溯时)
  2. 思路 B: 模拟执行体视角推演——假设自己就是子代理,尝试仅凭本任务书干活,卡点即缺口(适用场景: 槽位多、边界模糊、清单式核对易漏隐性缺口时)
- [ ] [M] **Step 3 渲染**: 按 `templates/fix-prompt-template.md` 产出 fix-prompt.md;遵守派发纪律: 绝对路径 / 单 S-unit 范围 / ≤3000 字符 / 禁花括号缩写 / 步骤枚举 ≤4
- [ ] [M] **Step 4 自检交付**: QC-FP-1..6 逐条核验,机检项跑命令附输出;全 PASS → READY

## QC-FP 自检表

| # | 判据 | 核验方式 |
|---|------|---------|
| QC-FP-1 | 自包含: 无代词悬指/裸文件名,全部绝对路径 | 机检: 关键锚 grep 出绝对路径 |
| QC-FP-2 | 根因 + 证据锚在位且可复现 | 机检: Read 抽查证据锚 file:line |
| QC-FP-3 | ≥1 机器可检查验收判据(命令可跑) | 机检: 实际跑验收命令 |
| QC-FP-4 | 单 S-unit 范围,修复目标唯一 | 与「任务一句话」对照 |
| QC-FP-5 | 无占位符/花括号缩写/「应该没问题」类措辞 | 机检: grep |
| QC-FP-6 | 未验证内容已隔离且显式标注 | 「未验证假设区」小节存在 |

## 门控铁律

- [P0] 无证据锚的根因禁入提示词主体,只可入「未验证假设区」
- [P0] 阻断级缺口禁出稿,列缺口清单交用户补
- [P0] 自检机检项禁止主观自报,必跑命令并附输出——无证据 = 未验证
- [P1] 同一核验方法连续失败 2 次 → 换策略,不重复同法重试

## 输出合约

- **fix-prompt.md**: <绝对路径>(按 templates/fix-prompt-template.md 渲染)
- **QC-FP 表**: QC-FP-1..6 逐条 PASS/FAIL + 证据(机检项附命令输出)
- **三态结论**(三枚举):
  - READY — QC-FP 全 PASS,可直接派发
  - PARTIAL — 非阻断缺口入「未验证假设区」显式标注,出稿但明示未验证面
  - BLOCKED — 根因未定位或验收不可判定,退回排查,不出稿

## 反模式

- ❌ 把未定位材料当排查结果 / ✅ 根因未定位 → BLOCKED 退回排查
- ❌ 无验收标准任务书 / ✅ ≥1 机器可检查验收判据必出
- ❌ 一次塞多个修复进同一任务书 / ✅ 单 S-unit,多修复点 → 拆
- ❌ 拿本 skill 替代排查 / ✅ 本 skill 只消费排查结论
- ❌ 「应该没问题」自报通过 / ✅ QC-FP 逐条证据,机检必附命令输出
