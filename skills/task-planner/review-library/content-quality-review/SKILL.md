# content-quality-review · 内容/撰写质量审查

review-library 兜底池的内容领域审核技能,消费 Rule 42.2 四级检测链第④层。当任务产出为文章、文案、博客、发布说明、教程等以文字撰写为主体的内容（非代码/测试/数据/图片）,且未命中更细的专用审查需求时,用本技能按内容质量维度做专项审查。
输出二值 `APPROVED` / `CHANGES_REQUESTED`,每条结论必须附机器可复现证据。

## 触发条件
- Rule 42.2 四级检测命中第④层「task-planner 内置 review-library 兜底池」,且任务类型匹配为「文字内容撰写/改写/发布」→ 命中本技能。
- 任务产出含 ≥1 篇成文内容（.md/.txt/网页文案/社交发布稿）,且文字量足以承载质量门（非标题级 3 行内 trivial 改动）。
- 交付前做「内容质量门」,或用户/审查者显式要求「撰写/文案质量」审查。
- 命中专用审查规则的任务优先专用规则;本技能只处理兜底池内内容面,不替代、不叠加。
- 纯代码、纯数据、纯图片任务不触发。
- 系列化/连载内容（多篇文章一组）额外做组级一致性审查：系列内术语、口径、时间线互查，篇间不矛盾。
- 营销/发布类内容含明确 SEO 目标（排名词/落地页流量）时，SEO 与可发现性维度按 P1 对待而非 P2。
- 含引用/注释的内容,逐条核对引文与出处对应（防张冠李戴）;引文未核实的按事实错误路径处理。

## 机械 SOP（77.2 锚点）
固定可复用的内容审查机械步骤,先跑完本段再进入逐维度清单,保证机械步骤可复现、可校验:

1. [M] 字数统计：`wc -w <file>` 记录总字数
2. [M] AI 腔检测：`grep -nE "此外\|综上所述\|值得注意的是\|不难发现\|总而言之" <file>` 检查套话密度
3. [M] 错别字检查：`grep -n "的的\|了了\|是是\|在在" <file>` 检查重复字
4. [M] 标题检查：`head -1 <file>` 确认标题含关键词 + ≤60 字符
5. [M] 结构检查：`grep -c "^#" <file>` 统计标题层级；`grep -c "^\- \[" <file>` 统计列表项
6. [M] 输出二值结论：PASS/FAIL + 逐行 `[P0|P1|P2] <file:line> — 问题 — 建议修法`

## 审查清单
每维度可直接执行（明确检查动作+判定标准）,禁空洞套话:
- [ ] [M] 事实准确性: 逐条抽取文中事实主张（人名/数字/日期/引用/技术结论）,列出清单并标注出处/「未验证」
- [ ] [A] 属实判定: 判定每条主张是否属实,事实错误属 P0 阻断项
  **可选思路**：
  1. 思路 A：逐条溯源——对每条主张查证出处（适用场景：主张少、可溯源）
  2. 思路 B：高风险优先——优先核验数字/引用/技术结论类高风险主张（适用场景：主张多、篇幅长）
- [ ] [A] 结构逻辑: 对照「论点-论据-结论」链抽查 3 段,论据支撑论点无跳跃、无循环论证,段落间有承接不互斥
  **可选思路**：
  1. 思路 A：抽段人工精读——对抽中段落逐句拆解「论点-论据-结论」链，标注跳跃/循环处（适用场景：论证型长文、逻辑密度高时）
  2. 思路 B：提纲还原法——抽取各级标题+段首句还原成大纲，检查骨架连贯与承接（适用场景：结构松散、段落数量多的长文）
- [ ] [A] 受众与语调: 声明目标受众后抽查 2 段,用语密度与受众匹配（专业/通俗不混搭失控）,全文语调无突变
  **可选思路**：
  1. 思路 A：术语密度统计——抽段统计专业术语/行话占比，与目标受众的预期密度对照（适用场景：技术/垂直领域文案）
  2. 思路 B：受众代入通读——以目标受众视角通读，标出理解门槛与语调突变处（适用场景：面向大众的科普/营销文案）
- [ ] [A] 标题与导语: 标题含可检索的核心关键词且不过度承诺;首 3 行导语独立可读,能概括全文主张
  **可选思路**：
  1. 思路 A：关键词检索模拟——用标题核心词在目标平台/搜索引擎检索，确认可命中且无夸大承诺（适用场景：SEO/内容分发场景）
  2. 思路 B：导语独立可读测试——仅读前 3 行判断能否概括全文主张，遮住正文验证（适用场景：新闻/长文阅读场景）
- [ ] [M] 冗余与啰嗦: 抽取全文 10% 篇幅做删减试算,记录删 30% 后语义变化;grep 重复句/同义反复
- [ ] [A] 冗余超标判定: 判定删减是否损义、冗余是否超标
  **可选思路**：
  1. 思路 A：删减试算——实际删减后读回判断语义完整（适用场景：段落独立性强）
  2. 思路 B：信息密度评估——评估单位篇幅承载信息量（适用场景：通篇铺陈、难逐段删减）
- [ ] [M] AI 腔与套话: grep 高频套话（「值得注意的是」「总而言之」「在当下」类模板句式）,密度超标或堆砌即命中
- [ ] [M] 错别字与标点: grep 中英标点混用、空格/换行符瑕疵;工具扫描错别字候选,逐处登记位置
- [ ] [A] 错字判定: 判定候选是否为真错字（vs 专有名词/有意用法）
  **可选思路**：
  1. 思路 A：工具扫描+人工复核——工具列候选后逐处人工确认（适用场景：长文、错字候选多）
  2. 思路 B：通读精查——通读一遍凭语感定位错字（适用场景：短文、工具覆盖不足）
- [ ] [M] 格式排版一致性: 抽查各级标题层级、列表符号、代码块语言标注全文统一,无跳级/混用
- [ ] [A] 原创性与抄袭面: 大段非引用文字对照来源核查改写深度,直接搬运无来源标注即命中
  **可选思路**：
  1. 思路 A：源文比对——对可疑长句/段落与已知来源逐句比对改写深度（适用场景：有明确来源清单/引用列表时）
  2. 思路 B：改写痕迹检测——检查句式结构与同义词替换痕迹，判断是否仅表层改写（适用场景：无明确来源、需快速筛查时）
- [ ] [M] SEO 与可发现性: 统计标题/摘要关键词出现频次与短句占比,与阈值比对;grep 关键词堆砌
- [ ] [A] 可发现性判定: 判定关键词布局是否自然、可读性是否达标
  **可选思路**：
  1. 思路 A：检索模拟——用目标词在平台/搜索引擎检索确认可命中（适用场景：SEO 目标明确）
  2. 思路 B：可读性量化——按短句占比/句长分布量化可读性（适用场景：长文、需客观指标）
- [ ] [M] 示例与数据支撑: 文中示例/数据可复核（命令实跑/数字溯源）,无「据说/大概」无源数据
- [ ] [M] 越界自检: 变更文件清单与任务书 scope_files 逐一对照,未触碰范围外文件

## 证据要求
- 呼应 Rule 43.1 证据先行:每个「已完成/正确/通过」的重要声称必须附机器可复现证据（命令+关键输出 / Read 路径+关键行 / diff 行号,三选一以上）。
- 未验证内容显式登记「未验证」,禁止混入完成表述;CHANGES_REQUESTED 的证据指向具体 file:line,建议修法可直接执行。
- 返回模板 evidence 字段的结论行必须可用同一命令重跑复现,抽查即对证据原文。
- 证据与结论同会话落盘 checkpoint/findings,保证跨会话可复查。
- 证据路径统一写 `file:line` 或「命令+关键输出」两种形式,与兜底池其他成员对齐。

## 输出合约
- 结论二值: `APPROVED`（清单全过且 P0/P1 = 0）或 `CHANGES_REQUESTED`（任一 P0/P1 命中）,结论置于审查报告首行供机械解析。
- CHANGES_REQUESTED 必须附逐条问题清单,格式每行一条: `[P0|P1|P2] <file:line> — 问题 — 建议修法`。
- 级别定义: P0=阻断（事实错误/严重失实/抄袭/不可回滚）; P1=合并前必须修复; P2=建议不阻断。
- APPROVED 必须附各维度实际跑过的证据关键输出摘要;「无证据应该没问题」不受理。
- 审查完成后清除本次 checkpoint 中的临时中间产物,只保留结论与证据索引。
