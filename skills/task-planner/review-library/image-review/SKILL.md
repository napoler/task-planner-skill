# image-review · 图片质量审查

review-library 兜底池的图片领域审核技能,消费 Rule 42.2 四级检测链第④层。当任务产出为图片（截图、设计图、AI 生成图、配图、图表渲染产物）且需要质量把关时,用本技能按图片质量维度做专项审查。
输出二值 `APPROVED` / `CHANGES_REQUESTED`,每条结论必须附机器可复现证据。

## 触发条件
- Rule 42.2 四级检测命中第④层「task-planner 内置 review-library 兜底池」,且任务类型匹配为「图片生成/截图/设计交付/配图审查」→ 命中本技能。
- 任务产出含 ≥1 张图片文件（.png/.jpg/.webp/.svg/.gif 等）或图片渲染产物（截图脚本输出、图表导出）,且图片质量影响交付结论。
- 交付前做「图片质量门」,或用户/审查者显式要求「图片/截图/设计图质量」审查。
- 命中专用审查规则的任务优先专用规则;本技能只处理兜底池内图片面,不替代、不叠加。
- 纯文字/纯代码任务不触发;纯代码任务中的图片仅作资源引用的,归 code 面审查。
- 批量图片交付（图集/多页截图）先全量过清单再抽 30% 逐张深查,抽样结论须注明抽样率。
- AI 生成图额外审查生成伪迹面（手指/文字乱码/结构错乱）,伪迹密度超标按 P0 处理。

## 审查清单
每维度可直接执行（明确检查动作+判定标准）,禁空洞套话:
- [ ] 清晰度与分辨率: 放大 100% 目视检查边缘,无可见模糊/块状伪影/压缩噪声;对已知目标尺寸（如 1080p 截图）核对实际像素,低于目标即命中
- [ ] 构图与主体突出: 主体在画面中位置与占比符合用途（标题图/缩略图/正文插图各有构图预期）,无关键元素贴边截断
- [ ] 文字可读性: 图内文字（标注/字幕/图表标签）在目标显示尺寸下可辨认;小字号与底色对比度不足即命中
- [ ] 色彩与对比度: 主色/背景对比度满足 WCAG 最低要求;叠加色盲模拟视角（或按红绿色盲感知预判）检查信息是否依赖单一色相传达
- [ ] 尺寸与宽高比合规: 实际像素与用途场景（缩略图/封面/全屏/头像）匹配,无拉伸变形、无异常留白
- [ ] 格式与压缩率合理: PNG/JPG/WebP 选型与内容匹配（照片选 JPG/WebP,含透明/文字/线条选 PNG）;文件体积与画质权衡合理,无 10MB 级冗余大图
- [ ] 与上下文内容匹配: 图文一致——图片内容与所在文档段落/标题/发布文案主张吻合,无张冠李戴
- [ ] 品牌一致性: 如适用,色调/标志/字体规范与品牌指南对照,无变形 Logo、无违和配色
- [ ] 版权与水印面: 图片来源可指认（自拍/自绘/授权/AI 生成）,无未声明的第三方素材与残留水印
- [ ] alt 文本与元数据完备: 发布场景 alt 文本覆盖图片语义;EXIF 等元数据无遗留内部信息（内部路径/测试标记）
- [ ] 越界自检: 变更文件清单与任务书 scope_files 逐一对照,未触碰范围外文件

## 证据要求
- 呼应 Rule 43.1 证据先行:每个「已完成/正确/通过」的重要声称必须附机器可复现证据（命令+关键输出 / Read 路径+关键行 / diff 行号,三选一以上）。
- 图片审查的证据=审查者实际查看图片（Read 图片文件/渲染预览）+逐项清单结论,禁未查看即下结论;「图片应该没问题」不受理。
- 未查看即下结论的结论行一律判定无效,审查者须补看后重签;未验证内容显式登记「未验证」,禁止混入完成表述。
- 批量抽查场景须逐张登记「已查看图清单+查看方式」,清单外图片不得计入通过结论。
- 返回模板 evidence 字段的结论行必须可重跑复现（同一张图 Read 即可复核）;证据与结论同会话落盘 checkpoint/findings,保证跨会话可复查。
- 证据路径统一写 `file:line`（指图片文件路径）或「命令+关键输出」两种形式,与兜底池其他成员对齐。

## 输出合约
- 结论二值: `APPROVED`（清单全过且 P0/P1 = 0）或 `CHANGES_REQUESTED`（任一 P0/P1 命中）,结论置于审查报告首行供机械解析。
- CHANGES_REQUESTED 必须附逐条问题清单,格式每行一条: `[P0|P1|P2] <图片文件路径> — 问题 — 建议修法`。
- 修法须含目标产物形态（重新生成/局部修图/更换来源/重裁切）,可直接交给生成或修图环节执行。
- 级别定义: P0=阻断（不可用/严重失实/版权风险）; P1=合并前必须修复; P2=建议不阻断。
- APPROVED 必须附逐项清单实际查看的证据摘要（看了哪张图、用什么方式）;「无证据应该没问题」不受理。
- 审查完成后清除本次 checkpoint 中的临时中间产物,只保留结论与证据索引。
- 结论绑定具体图片文件与版本（文件路径+修改时间戳）,图片被重新生成后须重审再放行。
