# image-review · 图片质量审查

review-library 兜底池的图片领域审核技能,消费 Rule 42.2 四级检测链第④层。当任务产出为图片（截图、设计图、AI 生成图、配图、图表渲染产物）且需要质量把关时,用本技能按图片质量维度做专项审查。
输出二值 `APPROVED` / `CHANGES_REQUESTED`,每条结论必须附机器可复现证据。

## 触发条件
- Rule 42.2 四级检测命中第④层「task-planner 内置 review-library 兜底池」,且任务类型匹配为「图片生成/截图/设计交付/配图审查」→ 命中本技能。
- 任务产出含 ≥1 张图片文件（.png/.jpg/.webp/.svg/.gif 等）或图片渲染产物（截图脚本输出、图表导出）,且图片质量影响交付结论。
- 交付前做「图片质量门」,或用户/审查者显式要求「图片/截图/设计图质量」审查。
- 命中专用审查规则的任务优先专用规则;本技能只处理兜底池内图片面,不替代、不叠加。
- 纯文字/纯代码任务不触发;纯代码任务中的图片仅作资源引用的,归 code 面审查。
- 批量图片交付（图集/多页截图）先全量过清单再抽 30% 逐张深查,抽样结论须注明抽样率。
- AI 生成图额外审查生成伪迹面（手指/文字乱码/结构错乱）,伪迹密度超标按 P0 处理。

## 机械 SOP（77.2 锚点）
固定可复用的图片审查机械步骤,先跑完本段再进入逐维度清单,保证机械步骤可复现、可校验:

1. [M] 截图采集：对每个审查目标生成 1920×1080 截图，文件名 `{id}-review-{seq}.png`
2. [M] 像素级检查：用 `identify -format '%wx%h' <file>` 确认分辨率
3. [M] 色彩对比度：`python3 -c "from PIL import Image; ..."` 或 `ImageMagick -format '%[fx:contrast]' <file>` 提取对比度值
4. [M] 品牌一致性：对照 `brand-guidelines.md`（如存在）grep 色值/字号
5. [M] 版权检查：`grep -ri "copyright\|©\|license" <file>` 检查水印/许可证标注
6. [M] 输出二值结论：PASS/FAIL + 逐行 `[P0|P1|P2] <file:line> — 问题 — 建议修法`

## 审查清单
每维度可直接执行（明确检查动作+判定标准）,禁空洞套话:
- [ ] [M] 清晰度与分辨率: Read 图片文件读取实际像素尺寸,与已知目标尺寸（如 1080p 截图）核对,低于目标即登记
- [ ] [A] 清晰度判定: 放大 100% 目视检查边缘,判定是否有可见模糊/块状伪影/压缩噪声
  **可选思路**：
  1. 思路 A：100% 放大逐区扫视——分区块放大检查边缘与高频细节（适用场景：细节密集图/截图）
  2. 思路 B：局部裁切对比——对可疑区裁切放大与正常区对比（适用场景：整体观感尚可但局部可疑时）
- [ ] [A] 构图与主体突出: 主体在画面中位置与占比符合用途（标题图/缩略图/正文插图各有构图预期）,无关键元素贴边截断
  **可选思路**：
  1. 思路 A：三分法/黄金比例检查——主体是否落在视觉焦点区（适用场景：摄影类/设计类图片）
  2. 思路 B：负空间比例检查——主体与背景面积比是否达标（适用场景：品牌 logo/产品图）
- [ ] [A] 文字可读性: 图内文字（标注/字幕/图表标签）在目标显示尺寸下可辨认;小字号与底色对比度不足即命中
  **可选思路**：
  1. 思路 A：目标尺寸预览——缩到实际显示尺寸（缩略图/移动端）核验文字可辨认性（适用场景：已知发布显示尺寸时）
  2. 思路 B：对比度量化——实测文字与底色对比度是否达 WCAG 阈值（适用场景：小字号或低对比配色时）
- [ ] [M] 色彩与对比度: 取主色/背景色值计算对比度比值,与 WCAG 最低要求比对
- [ ] [A] 色觉可达性判定: 叠加色盲模拟视角（或按红绿色盲感知预判）判定信息是否依赖单一色相传达
  **可选思路**：
  1. 思路 A：色盲模拟工具——用模拟滤镜渲染后目视检查（适用场景：有图像处理/滤镜工具时）
  2. 思路 B：色相感知预判——按红绿色盲感知规律人工预判色相区分度（适用场景：无工具、快速筛查时）
- [ ] [M] 尺寸与宽高比合规: 读取实际像素与宽高比,与用途场景（缩略图/封面/全屏/头像）规格表比对
- [ ] [A] 形变判定: 目视判定有无拉伸变形、异常留白
  **可选思路**：
  1. 思路 A：宽高比核算——比对声明宽高比与实际是否一致，判定是否拉伸（适用场景：有规格表时）
  2. 思路 B：视觉形变检查——目视主体是否变形、边缘留白是否异常（适用场景：无规格、凭观感判断）
- [ ] [M] 格式与压缩率合理: 读取文件格式与体积,与内容类型选型规则（照片选 JPG/WebP,含透明/文字/线条选 PNG）比对;体积超阈值即登记
- [ ] [A] 权衡合理性判定: 判定体积与画质权衡是否合理、有无 10MB 级冗余大图
  **可选思路**：
  1. 思路 A：规则匹配——按内容类型套选型规则直接判定格式是否合适（适用场景：内容类型明确时）
  2. 思路 B：画质-体积权衡——同图不同质量压缩对比，判定是否可无损降体积（适用场景：大体积图、需压减时）
- [ ] [A] 与上下文内容匹配: 图文一致——图片内容与所在文档段落/标题/发布文案主张吻合,无张冠李戴
  **可选思路**：
  1. 思路 A：段落-图片逐一对照——读图片所在段落/标题，核对图片主张与文字是否吻合（适用场景：图文混排文档）
  2. 思路 B：反查图片语义——先独立描述图片内容，再回查是否与发布文案主张一致（适用场景：营销/社媒配图）
- [ ] [A] 品牌一致性: 如适用,色调/标志/字体规范与品牌指南对照,无变形 Logo、无违和配色
  **可选思路**：
  1. 思路 A：规范逐项对照——色值/字体/Logo 尺寸与品牌指南逐项比对（适用场景：有正式品牌指南时）
  2. 思路 B：视觉并置对比——与既有品牌素材并排目视，判断整体观感是否违和（适用场景：无量化规范、凭观感判断时）
- [ ] [A] 版权与水印面: 图片来源可指认（自拍/自绘/授权/AI 生成）,无未声明的第三方素材与残留水印
  **可选思路**：
  1. 思路 A：元数据/来源溯源——查 EXIF/来源记录/AI 生成标记，确认来源可指认（适用场景：有元数据或来源台账可查时）
  2. 思路 B：视觉水印排查——放大检查边缘/角落残留水印或第三方素材特征（适用场景：无元数据、来源不明时）
- [ ] [M] alt 文本与元数据完备: 读取 EXIF 等元数据,grep 内部路径/测试标记等敏感信息;核验发布场景 alt 文本存在性
- [ ] [A] alt 语义覆盖判定: 判定 alt 文本是否覆盖图片语义（而非仅占位）
  **可选思路**：
  1. 思路 A：语义覆盖核验——比对 alt 文本与图片实际内容是否一致（适用场景：无障碍要求高的发布场景）
  2. 思路 B：读屏模拟——以读屏视角看 alt 能否传达图片信息（适用场景：信息图/图表类图片）
- [ ] [M] 越界自检: 变更文件清单与任务书 scope_files 逐一对照,未触碰范围外文件

## 证据要求
- 呼应 Rule 43.1 证据先行:每个「已完成/正确/通过」的重要声称必须附机器可复现证据（命令+关键输出 / Read 路径+关键行 / diff 行号,三选一以上）。
- 图片审查的证据=审查者实际查看图片（Read 图片文件/渲染预览）+逐项清单结论,禁未查看即下结论;「图片应该没问题」不受理。
- 未查看即下结论的结论行一律判定无效,审查者须补看后重签;未验证内容显式登记「未验证」,禁止混入完成表述。
- 批量抽查场景须逐张登记「已查看图清单+查看方式」,清单外图片不得计入通过结论。
- 返回模板 evidence 字段的结论行必须可重跑复现（同一张图 Read 即可复核）;证据与结论同会话落盘 checkpoint/findings,保证跨会话可复查。
- 证据路径统一写 `file:line`（指图片文件路径）或「命令+关键输出」两种形式,与兜底池其他成员对齐。

## 输出合约
- 结论二值: `APPROVED`（清单全过且 P0/P1 = 0）或 `CHANGES_REQUESTED`（任一 P0/P1 命中）,结论置于审查报告首行供机械解析。
- CHANGES_REQUESTED 必须附逐条问题清单,格式每行一条: `[P0|P1|P2] <图片文件路径> — 问题 — 建议修法`。
- 修法须含目标产物形态（重新生成/局部修图/更换来源/重裁切）,可直接交给生成或修图环节执行。
- 级别定义: P0=阻断（不可用/严重失实/版权风险）; P1=合并前必须修复; P2=建议不阻断。
- APPROVED 必须附逐项清单实际查看的证据摘要（看了哪张图、用什么方式）;「无证据应该没问题」不受理。
- 审查完成后清除本次 checkpoint 中的临时中间产物,只保留结论与证据索引。
- 结论绑定具体图片文件与版本（文件路径+修改时间戳）,图片被重新生成后须重审再放行。
