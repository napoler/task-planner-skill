# alignment-review · 对齐/同步一致性审查

review-library 兜底池的对齐领域审核技能,消费 Rule 42.2 四级检测链第④层。任务产出发生一次变更后,用本技能审查「所有关联产物是否同步更新」——跨文档、跨代码、跨配置、跨引用的一致性。
输出二值 `APPROVED` / `CHANGES_REQUESTED`,每条结论必须附机器可复现证据。

## 触发条件
- Rule 42.2 四级检测命中第④层「task-planner 内置 review-library 兜底池」,且任务类型涉及跨产物变更、联动修改或多副本文件 → 命中本技能。
- 任务变更行为规格/接口/计数声明/术语/锚点,而文档、代码、配置、引用各自独立成实体需要联动。
- 任务涉及同一实体多副本（多部署位/多份分发）,或模板改动可能牵连已生成实例。
- 交付前做「对齐/同步一致性门」,或用户/审查者显式要求审查「联动处是否全部更新」。
- 纯新增单产物、无任何既有联动声明（新文件/新目录/无旧引用）的任务不触发（由 general-review 兜底）。
- 命中专用技能的任务优先专用技能;本技能只处理专用技能通过后的对齐余量,不替代、不叠加。
- **写入动作前（验证优先,本条为闸门级触发）**: 任何对既有文档/文件的内容追加或更新,在写入前即命中本技能的写入前校验闸门（见下节）——验证优先于修正,流程初期即完成关键确认。

## 写入前校验闸门（验证优先）
任何对既有文档/文件的追加或更新,写入前必须完成版本一致性校验（验证优先——修正成本在写入前远低于写入后）:

1. **读取最新态**: Read 目标文件当前完整内容（禁凭记忆/旧副本操作）
2. **对照待写内容**: 将待追加/更新内容与现有内容逐段对照
3. **识别三类问题**: 前后版本不一致（同一事实两种表述）/重复内容（语义相同的冗余段）/过期信息（已被新版本取代的旧表述）
4. **整理后写入**: 按最新有效版本合并——更新过时表述、合并重复段、删除冗余内容;发现冲突时优先整理再写入,禁止在冲突未整理的情况下直接追加
5. **输出变更记录**: 按下节格式输出本次对齐的变更记录

**未经一致性校验，不直接追加新内容。**（用户 2026-09-30 原话,闸门级纪律）

## 审查清单
每条可直接执行（明确检查动作+判定标准）,禁空洞套话;所列案例均有本仓真实先例背书:
- [ ] 文档↔代码同步: grep 改动涉及的行为措辞在 README/API 文档/注释中的锚点,与实现实际行为逐一 diff（案例: 42.2 三级→四级规格变更,42.5 行内锚描述未随行同步——CR 复核 caught 于 selftest 注释/实文对照）
- [ ] 计数与枚举联动: grep 「N 类/N 项/池成员 N/M/NN 行」类数量与枚举声明的全部出现处,与 `ls | wc -l` 等实际实体计数逐一对照（案例: RL-01 计数 10→11 级联、「10 类」枚举、SR-12 行数 40）
- [ ] 引用完整性: 抽取变更文件中指向其他实体的链接/锚点/路径/文件名,对每个目标 `grep -n`/Read 验存在性;任一失效引用（目标改名/移动/删除）= 失败
- [ ] 术语一致性: 对同一概念的多个叫法变体做全仓 grep 对照,确认新旧措辞不混用（如「三级」vs「四级」漂移）,旧措辞零残留
- [ ] 多副本/多部署位同步: `find` 枚举同一文件的全部物理副本,逐对 `diff -q`;任一副本间存在差异 = P0（三部署位 diff 惯例）
- [ ] 模板与实例回溯: 模板/口径澄清变更后,grep 枚举已生成实例,检查是否仍残留旧枚举/旧结构;需回溯而未回溯 = P1（案例: B 类澄清后 general-review 枚举未回溯,CR P1）
- [ ] 变更日志与实际变更同步: CHANGELOG/INDEX 声称的变更逐条 diff git diff 实际文件清单;「声称有但没改」或「改了没声称」任一方向 = P1
- [ ] 版本对齐: Read frontmatter/版本号/日期声明,与 `git log -1 --format=%cs` 及文件实际值比对;声明与实际不符 = P1
- [ ] 跨文件语义互斥: 将分散在多文件的同一规则表述逐处提取,与档位/路由/判定表逐级对照,确认无语义互斥（案例: 43.2 档位词汇与路由表逐级对照）
- [ ] 守卫锚与被守护对象级联: 被守护文件（selftest/断言锚对象）变更时,grep 枚举指向它的所有断言锚,验证锚已同步更新;锚漂移 = P0（案例: SR-11/12 级联漂移两连发）
- [ ] 索引/登记联动: 新增/改名实体是否在 INDEX/池枚举/目录类登记文件同步登记,登记中的 N/M 编号与实际实体数一致（案例: 池 10→11 登记级联）
- [ ] i18n 对齐（可补强）: 实体含翻译副本时,grep diff 两份 key 集合逐一对照,确认无缺 key、无文案漂移
- [ ] schema/契约对齐（可补强）: 接口/数据 schema 声明字段列表与产出方实际 payload 逐字段 diff,确认无类型漂移、无未声明字段
- [ ] 越界自检: 变更文件清单与任务书 scope_files 逐一对照,未触碰范围外文件

## 证据要求
- 呼应 Rule 43.1 证据先行:每个「已同步/已全部更新/无残留」的重要声称必须附机器可复现证据（命令+关键输出 / Read 路径+关键行 / diff 行号,三选一以上）。
- 本领域断言优先机器可复现命令: 计数/枚举对照用 grep 计数 vs 实体 `wc -l` 输出;引用失效用 grep 退出码与 diff 原文;「目测检查」不受理。
- 未验证内容显式登记「未验证」,禁止混入完成表述;CHANGES_REQUESTED 的证据指向具体 file:line,建议修法可直接执行。
- 返回模板 evidence 字段的结论行必须可用同一命令重跑复现,抽查即对证据原文。
- 证据与结论同会话落盘 checkpoint/findings,保证跨会话可复查;证据路径统一写 `file:line` 或「命令+关键输出」两种形式,与兜底池其他成员对齐。

## 变更记录输出
每次执行写入前校验或对齐整理,必须输出变更记录（机器可读,供复查与回溯）:

| 字段 | 说明 |
|------|------|
| 更新 | 本次修改了哪些表述（旧→新对照） |
| 合并 | 哪些重复/冲突段被合并,依据哪个版本为准 |
| 删除 | 哪些冗余/过期内容被移除,移除理由 |
| 依据版本 | 判定"最新有效版本"的依据（时间戳/来源权威性/明确声明） |
| 残留冲突 | 未能自动裁决、需人工复核的冲突点（无则写"无"） |

变更记录随交付物落盘（progress.md 或审查报告）,禁止只执行不记录。

## 输出合约
- 结论二值: `APPROVED`（清单全过且 P0/P1 = 0）或 `CHANGES_REQUESTED`（任一 P0/P1 命中）,结论置于审查报告首行供机械解析。
- CHANGES_REQUESTED 必须附逐条问题清单,格式每行一条: `[P0|P1|P2] <file:line> — 问题 — 建议修法`。
- 级别定义（本技能特化）: P0=阻断（用户可见面失效引用/声明与事实不符/多副本不同步）; P1=合并前必须修复; P2=建议不阻断。
- APPROVED 必须附各维度实际跑过的证据关键输出摘要;「无证据应该没问题」不受理。
- 审查完成后清除本次 checkpoint 中的临时中间产物,只保留结论与证据索引。
