# ui-quality-review · UI/前端质量审查

review-library 兜底池的前端领域审核技能,消费 Rule 42.2 四级检测链第④层。当任务产出为页面、组件、交互流程等 UI/前端代码或界面变更,且需要质量把关时,用本技能按 UI 质量维度做专项审查。
输出二值 `APPROVED` / `CHANGES_REQUESTED`,每条结论必须附机器可复现证据。

## 触发条件
- Rule 42.2 四级检测命中第④层「task-planner 内置 review-library 兜底池」,且任务类型匹配为「UI/前端页面/组件/交互流程交付」→ 命中本技能。
- 任务产出含前端源码（组件/模板/样式）或界面截图产物,且界面质量影响交付结论。
- 交付前做「UI 质量门」,或用户/审查者显式要求「界面/交互/前端质量」审查。
- 命中专用审查规则的任务优先专用规则;本技能只处理兜底池内 UI 面,不替代、不叠加。
- 纯后端/纯数据任务不触发;仅改动 API 契约而不动界面的,归 code 面审查。
- 审查需附界面证据（浏览器实测截图/渲染预览）,无运行环境时须显式登记「仅静态审查+未实测」并下调置信度。
- 多端交付（桌面+移动）时响应式断点面按 P1 对待而非 P2,逐断点各取 1 屏抽查。

## 审查清单
每维度可直接执行（明确检查动作+判定标准）,禁空洞套话:
- [ ] 布局完整性: 目视检查目标分辨率下各区域,无错位/溢出/截断/重叠;长文案与极端数据（空/超长/特殊字符）各取 1 样本实测不破坏布局
- [ ] 响应式表现: 在声明的关键断点（移动/平板/桌面）各取 1 屏截图,断点间无布局崩坏、无横向滚动条意外出现
- [ ] 交互反馈: 抽查主按钮/表单 3 个交互点,hover/active/loading/错误态反馈存在且可感知,无点了无响应的死交互
- [ ] 可访问性: 键盘 Tab 走查主流程无焦点陷阱;正文对比度达 WCAG AA 最低要求;交互控件用语义标签/aria 可被读屏识别
- [ ] 文案一致性: grep 同类操作（保存/提交/取消）的按钮与提示语全文措辞统一,无同义词混用、无中英夹杂失控
- [ ] 加载性能感知: 首屏无白屏长尾,重列表/重区块有骨架屏/懒加载;主路径等待有进度提示,无「点了没反应超过 5s」死等
- [ ] 空态与异常态设计: 取空数据/加载失败/无权限 3 态实测,有显式空态文案与重试/兜底出口,非裸白屏或报错堆栈
- [ ] 浏览器兼容面: 按声明的兼容矩阵抽查目标浏览器,无某浏览器下样式/功能静默失效;未声明矩阵时登记「兼容面未定」
- [ ] 视觉规范一致性: 抽查 3 个页面/组件,间距/字号/色板与设计规范（design token/样式变量）对照,无游离魔法值
- [ ] 关键路径可用性实测: 走一遍核心用户路径（如注册→首用）,可完成且无阻断报错;实测路径留截图/日志证据
- [ ] 越界自检: 变更文件清单与任务书 scope_files 逐一对照,未触碰范围外文件

## 证据要求
- 呼应 Rule 43.1 证据先行:每个「已完成/正确/通过」的重要声称必须附机器可复现证据（命令+关键输出 / Read 路径+关键行 / diff 行号,三选一以上）。
- UI 审查的证据=实测界面产物（截图/渲染预览/浏览器日志）+逐项清单结论,禁未实测即下结论;「界面应该没问题」不受理。
- 未实测维度显式登记「未实测+原因」,禁止混入通过表述;CHANGES_REQUESTED 的证据指向具体 file:line 或截图文件名,建议修法可直接执行。
- 返回模板 evidence 字段的结论行必须可重跑复现（同一命令/同一页面重开即可复核）;证据与结论同会话落盘 checkpoint/findings,保证跨会话可复查。
- 证据路径统一写 `file:line` 或「命令+关键输出」两种形式,与兜底池其他成员对齐。

## 输出合约
- 结论二值: `APPROVED`（清单全过且 P0/P1 = 0）或 `CHANGES_REQUESTED`（任一 P0/P1 命中）,结论置于审查报告首行供机械解析。
- CHANGES_REQUESTED 必须附逐条问题清单,格式每行一条: `[P0|P1|P2] <file:line|截图名> — 问题 — 建议修法`。
- 修法须指认到组件/文件级（文件+行号或组件名）,可直接交给前端开发执行。
- 级别定义: P0=阻断（主路径不可用/布局崩坏/安全可见缺陷）; P1=合并前必须修复; P2=建议不阻断。
- APPROVED 必须附各维度实测证据关键输出摘要;「无证据应该没问题」不受理。
- 审查完成后清除本次 checkpoint 中的临时中间产物,只保留结论与证据索引。
- 截图证据须与审查时页面状态一致（同构建/同数据样本）,防后续改动使结论失效。
