# documentation-review · 文档质量审查

review-library 兜底池的文档领域审核技能,消费 Rule 42.2 四级检测链第④层。当任务产出为 README、API 参考、操作手册、CHANGELOG、教程页等以技术文档为主体的文档,且未命中更细的专用审查需求时,用本技能按文档质量维度做专项审查。
输出二值 `APPROVED` / `CHANGES_REQUESTED`,每条结论必须附机器可复现证据。

## 触发条件
- Rule 42.2 四级检测命中第④层「task-planner 内置 review-library 兜底池」,且任务类型匹配为「技术文档撰写/修订/发布」→ 命中本技能。
- 任务产出含 ≥1 个文档文件（README/API 手册/操作指南/.md 文档页）,且文档面向使用者（非纯内部草稿）,需过可执行性+一致性门。
- 交付前做「文档质量门」,或用户/审查者显式要求「文档/README 质量」审查。
- 命中专用审查规则的任务优先专用规则;本技能只处理兜底池内文档面,不替代、不叠加。
- 纯代码、纯数据、纯营销文案任务不触发（营销文案走 content-quality-review）。
- 多文档集（API 文档站、手册分册）交付时,除单篇审查外,额外做集级一致性：交叉引用可达、共享术语表对齐、目录树无死页。
- 文档面向外部用户（发布到仓库/GitHub/官网）时,示例命令须在干净环境重放一遍,禁只在本机带缓存跑通。
- CHANGELOG/版本说明类文档额外核对：条目与代码 diff 一一对应,无漏记的破坏性变更（breaking change 显式标注）。
- 已废弃文档（旧版本指南/被替代方案）确认有废弃声明与跳转指引,禁止静默留死页。

## 审查清单
每维度可直接执行（明确检查动作+判定标准）,禁空洞套话:
- [ ] 准确性可复现: 抽取文中 3 条示例命令/路径/参数实跑或逐字核对真实环境,能复现才算过,复现失败即 P1
- [ ] 完整性闭环: 按「安装-配置-使用-故障排除」四段逐一勾选,缺段显式登记;每个配置项都有默认值说明
- [ ] 结构导航: 目录与正文标题层级一一对应;长文有锚点可跳转,TOC 锚点逐个验证不 404
- [ ] 版本一致性: 文档描述的行为/参数与当前代码实际行为核对（跑代码或读源码）,不同步即命中
- [ ] 受众分级: 确认文档定位（入门/参考/运维）,入门篇无未解释术语,参考篇无冗余背景铺垫
- [ ] 示例可复制: 每段代码块可整段复制直接执行（无伪代码占位、变量有前置定义、语言标注正确）
- [ ] 术语一致性: grep 同一概念多种叫法（如「实例/对象/资源」混用）,全文统一或显式声明别名
- [ ] 链接有效性: 逐个抽验内外部链接可达,相对链接相对当前文档路径实打一遍
- [ ] 更新日期与变更记录: 头部有最后更新日期;功能变更文档段落与 CHANGELOG 时间线对得上
- [ ] 可访问性: 图片有 alt 文本、表格有表头标注、代码块有独立上下文不依赖仅颜色区分
- [ ] 越界自检: 变更文件清单与任务书 scope_files 逐一对照,未触碰范围外文件

## 证据要求
- 呼应 Rule 43.1 证据先行:每个「已完成/正确/通过」的重要声称必须附机器可复现证据（命令+关键输出 / Read 路径+关键行 / diff 行号,三选一以上）。
- 未验证内容显式登记「未验证」,禁止混入完成表述;CHANGES_REQUESTED 的证据指向具体 file:line,建议修法可直接执行。
- 返回模板 evidence 字段的结论行必须可用同一命令重跑复现,抽查即对证据原文。
- 证据与结论同会话落盘 checkpoint/findings,保证跨会话可复查。
- 证据路径统一写 `file:line` 或「命令+关键输出」两种形式,与兜底池其他成员对齐。

## 输出合约
- 结论二值: `APPROVED`（清单全过且 P0/P1 = 0）或 `CHANGES_REQUESTED`（任一 P0/P1 命中）,结论置于审查报告首行供机械解析。
- CHANGES_REQUESTED 必须附逐条问题清单,格式每行一条: `[P0|P1|P2] <file:line> — 问题 — 建议修法`。
- 级别定义: P0=阻断（示例命令实际会损坏数据/文档严重失实/不可回滚）; P1=合并前必须修复; P2=建议不阻断。
- APPROVED 必须附各维度实际跑过的证据关键输出摘要;「无证据应该没问题」不受理。
- 审查完成后清除本次 checkpoint 中的临时中间产物,只保留结论与证据索引。
