# data-quality-review · 数据质量审查

review-library 兜底池的数据领域审核技能,消费 Rule 42.2 四级检测链第④层。当任务产出为数据集、ETL/管道输出、数据库迁移结果、统计口径变更等以数据交付为主体的成果,且未命中更细的专用审查需求时,用本技能按数据质量维度做专项审查。
输出二值 `APPROVED` / `CHANGES_REQUESTED`,每条结论必须附机器可复现证据。

## 触发条件
- Rule 42.2 四级检测命中第④层「task-planner 内置 review-library 兜底池」,且任务类型匹配为「数据集产出/管道加工/迁移核对」→ 命中本技能。
- 任务产出含 ≥1 份数据文件/表（CSV/JSON/表数据/管道落盘物）,且下游有消费方或进库即需过质量门（非探索性 scratch 数据）。
- 交付前做「数据质量门」,或用户/审查者显式要求「数据质量/口径核对」审查。
- 命中专用审查规则的任务优先专用规则;本技能只处理兜底池内数据面,不替代、不叠加。
- 纯代码逻辑、纯文档、纯文案任务不触发。
- 增量数据（追加批次）交付时,额外核对批次间边界：时间窗无重叠无缺口,增量批次可独立重放。
- 数据进生产库/对外交付前,除抽样比对外,须跑全量口径校验（总行数/金额合计/主键计数）,抽样结果不得替代全量结论。
- 迁移类任务额外做回滚演练确认：迁移产物可弃置、源库未破坏、切换点双向可逆。
- 派生/统计类数据（聚合表、指标口径）核对加工脚本版本与数据版本配对,口径漂移显式登记。

## 审查清单
每维度可直接执行（明确检查动作+判定标准）,禁空洞套话:
- [ ] 完整性: 核对行数与预期口径、空值率与必填字段非空约束（逐列查 NULL/空串占比）,缺口登记清单
- [ ] 准确性: 抽样 3 行以上比对真源（源库/源文件/上游 API 返回）,逐字段核对,抽样记录入 evidence
- [ ] 一致性: 跨表/跨文件核对主键对齐与枚举值域（同一枚举多文件取值集合一致）,类型口径统一
- [ ] 时效性: 确认新鲜度满足下游 SLA（最大数据时间戳 vs 期望窗口）,时间戳字段可解释无未来值
- [ ] 唯一性: 按业务主键跑重复检测（count distinct 比对总行数）,重复行归因（源重发/合并误）
- [ ] 格式合规: 抽 20 行核对类型/编码/列顺序与 Schema 一致,无漂移（列增删/类型隐变）
- [ ] 异常值与离群点: 数值列跑 min/max/分位数扫,离群点逐个归因（真实异常 vs 脏数据）,不静默截断
- [ ] 血缘与转换可追溯: 每步加工有输入→输出映射记录（脚本/SQL 可重放）,口径变更有版本标注
- [ ] 抽样验证记录: 本次审过的抽样命令+结果摘要落 evidence,可复现,非「目测正常」
- [ ] 隐私合规: grep PII 面（手机号/邮箱/证件号/IP）,确认脱敏策略符合任务书要求,无泄漏字段进交付
- [ ] 越界自检: 变更文件清单与任务书 scope_files 逐一对照,未触碰范围外文件

## 证据要求
- 呼应 Rule 43.1 证据先行:每个「已完成/正确/通过」的重要声称必须附机器可复现证据（命令+关键输出 / Read 路径+关键行 / diff 行号,三选一以上）。
- 未验证内容显式登记「未验证」,禁止混入完成表述;CHANGES_REQUESTED 的证据指向具体 file:line 或 表名+字段,建议修法可直接执行。
- 返回模板 evidence 字段的结论行必须可用同一命令重跑复现,抽查即对证据原文。
- 证据与结论同会话落盘 checkpoint/findings,保证跨会话可复查。
- 证据路径统一写 `file:line` 或「命令+关键输出」两种形式,与兜底池其他成员对齐。

## 输出合约
- 结论二值: `APPROVED`（清单全过且 P0/P1 = 0）或 `CHANGES_REQUESTED`（任一 P0/P1 命中）,结论置于审查报告首行供机械解析。
- CHANGES_REQUESTED 必须附逐条问题清单,格式每行一条: `[P0|P1|P2] <file:line> — 问题 — 建议修法`。
- 级别定义: P0=阻断（数据失实/PII 泄漏/主键不唯一不可回滚）; P1=合并前必须修复; P2=建议不阻断。
- APPROVED 必须附各维度实际跑过的证据关键输出摘要;「无证据应该没问题」不受理。
- 审查完成后清除本次 checkpoint 中的临时中间产物,只保留结论与证据索引。
