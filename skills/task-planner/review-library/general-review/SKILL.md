# general-review · 通用综合质量审核

review-library 兜底池的通用质量审核技能,Rule 42.2 四级检测链中的「兜底的兜底」。当任务产出类型未命中对应领域专用审核技能（code/test/security/image/content/documentation/data/UI/release/alignment）,或任务为混合领域、无单一专用技能可完整覆盖时,用本技能做最终综合质量审查。
输出二值 `APPROVED` / `CHANGES_REQUESTED`,每条结论必须附机器可复现证据。

## 触发条件
- Rule 42.2 四级检测命中第④层「task-planner 内置 review-library 兜底池」,且任务类型未命中池内任一领域专用审核技能（其余 10 个）→ 命中本技能作通用兜底。
- 任务产出为混合领域（文档+配置+脚本混合等）,无单一专用技能可完整覆盖。
- 交付前做「最终综合质量门」,或用户/审查者显式要求「通用综合质量」审查。
- 命中专用技能的任务优先专用技能;本技能只处理专用技能通过后的未覆盖余量,不替代、不叠加。
- 纯调研/只读、无交付物产出的任务不触发。

## 审查清单
十维度各 1 条起,每条可直接执行（明确检查动作+判定标准）,禁空洞套话:
- [ ] [M] 正确性: 对每条核心路径跑最直接验证命令（测试/dry-run/关键行重读）,记录结果
- [ ] [A] 规格一致性判定: 判定行为是否与任务书规格一致,不止「能编译/能跑」
  **可选思路**：
  1. 思路 A：规格逐条对照——以任务书规格为基准逐路径核验（适用场景：规格明确、路径可枚举）
  2. 思路 B：反例构造——构造规格边界反例观察行为（适用场景：规格模糊、需反推预期）
- [ ] [M] 完整性: 对照需求清单（VC/acceptance/决策点）逐条勾选,确认无遗漏项、无范围外扩写,未做项显式登记
- [ ] [M] 一致性: grep 新增措辞/接口/数字字面的全局锚点,列出全部出现位置与差异
- [ ] [A] 漂移/互斥判定: 判定差异是否构成语义漂移或互斥（如「三级」vs「四级」措辞、越界数字）
  **可选思路**：
  1. 思路 A：既有条款为准——以既有条款为基准，新措辞向其对齐（适用场景：既有条款权威稳定）
  2. 思路 B：最新口径为准——以本次变更为准，同步更新既有锚点（适用场景：本次即口径升级）
- [ ] [M] 可维护性: grep 死代码/重复逻辑/硬编码魔数;核对改动范围与注释「原因+时间+原行为」三要素
- [ ] [A] 最小性判定: 判定改动是否最小、注释是否达意
  **可选思路**：
  1. 思路 A：diff 逐行追溯——逐行 diff 确认改动可追溯到需求（适用场景：改动集中）
  2. 思路 B：结构走查——按模块走查是否有重复/死代码（适用场景：改动分散、跨模块）
- [ ] [M] 文档: 确认改动的函数/脚本/配置项 docstring/注释完备,无 TODO 占位替代修改说明
- [ ] [M] 测试: 跑既有 selftest/测试套件记录结果;核对新功能是否有测试或登记「无测试+原因」
- [ ] [A] 回归/豁免判定: 判定是否有回归、无测试项是否可豁免,不静默跳过
  **可选思路**：
  1. 思路 A：基线对照——与改动前基线比对差异（适用场景：有基线记录）
  2. 思路 B：豁免清单——按可豁免类型清单分档（适用场景：改动量大、需快速分档）
- [ ] [M] 安全基线: 确认无硬编码密钥、无权限提升、无未授权的 `rm -rf`/`git reset --hard`/`curl|bash` 类危险命令
- [ ] [M] 性能基线: grep 高频 O(n²) 循环、大文件整读入内存、关键路径新增阻塞等待
- [ ] [A] 性能风险判定: 判定新增模式是否实际构成性能风险
  **可选思路**：
  1. 思路 A：复杂度分析——静态分析循环/数据规模判定复杂度（适用场景：算法类改动）
  2. 思路 B：基准测试——对关键路径跑基准对比（适用场景：有性能测试环境）
- [ ] [M] 可回滚性: 核对回滚点（worktree/分支/基线 commit）明确性;git status 确认改动未混入用户工作树
- [ ] [A] 可复原判定: 判定回滚是否可实际演示复原
  **可选思路**：
  1. 思路 A：演练复原——实际执行回滚操作演示复原（适用场景：隔离环境可演练）
  2. 思路 B：回滚点核验——核对回滚点是否精确覆盖全部改动（适用场景：无法演练、静态核验）
- [ ] [M] 证据留痕: 报告中每条结论附机器可复现证据（file:line/命令+输出）,禁「推测/应该没问题」
- [ ] [M] 越界自检: 变更文件清单与任务书 scope_files 逐一对照,未触碰范围外文件
- [ ] [M] 幂等性: 同一操作重复执行结果一致,无重复项/脏数据类副作用累积
- [ ] [M] 回归抽查: 抽取未改动路径的旧行为样本,跑验证命令记录结果
- [ ] [A] 静默回归判定: 判定样本行为是否与改动前一致、有无静默回归
  **可选思路**：
  1. 思路 A：样本对照——与改动前行为样本逐一对照（适用场景：有历史行为记录）
  2. 思路 B：主路径复跑——重跑未改动主路径看是否异常（适用场景：无历史记录、凭当前观察）
- [ ] [M] 配置/环境: 配置项取值与文档一致,无默认值掩盖缺失（`dict.get` 兜底、`x or default` 混淆 falsy）
- [ ] [A] 命名/可读性: 新增命名与实体语义相符,无过度抽象、注释与代码无语义落差
  **可选思路**：
  1. 思路 A：陌生人视角——不看上下文仅凭命名推断语义，检验是否自解释（适用场景：公共 API/导出符号）
  2. 思路 B：一致性对照——与邻近既有命名风格逐项对照（适用场景：既有代码库内的新增符号）

## 证据要求
- 呼应 Rule 43.1 证据先行:每个「已完成/正确/通过」的重要声称必须附机器可复现证据（命令+关键输出 / Read 路径+关键行 / diff 行号,三选一以上）。
- 未验证内容显式登记「未验证」,禁止混入完成表述;CHANGES_REQUESTED 的证据指向具体 file:line,建议修法可直接执行。
- 返回模板 evidence 字段的结论行必须可用同一命令重跑复现,抽查即对证据原文。
- 证据与结论同会话落盘 checkpoint/findings,保证跨会话可复查。
- 本节为兜底池 11 技能共同对标的最小证据标准:证据路径统一写 `file:line` 或「命令+关键输出」两种形式,复查格式统一。

## 输出合约
- 结论二值: `APPROVED`（清单全过且 P0/P1 = 0）或 `CHANGES_REQUESTED`（任一 P0/P1 命中）,结论置于审查报告首行供机械解析。
- **审查对象总清单（Rule 70①）**：报告须附本次审查对象文件清单（绝对路径+逐项一句话），使收报告者无需追问即知审了什么。
- CHANGES_REQUESTED 必须附逐条问题清单,格式每行一条: `[P0|P1|P2] <file:line> — 问题 — 建议修法`。
- 级别定义: P0=阻断（错误/安全风险/不可回滚）; P1=合并前必须修复; P2=建议不阻断。
- APPROVED 必须附各维度实际跑过的证据关键输出摘要;「无证据应该没问题」不受理。
- 审查完成后清除本次 checkpoint 中的临时中间产物,只保留结论与证据索引。
