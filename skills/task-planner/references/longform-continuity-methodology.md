# 长文与连续创作连续性方法论（longform-continuity）

> 目标：系统性解决长篇小说/剧集/长论文/长报告在续写与扩写中的“前后遗忘、设定漂移、后文静默改前文”问题。核心思路：**项目级资产为事实源 + 大纲先行 + 动笔前全局检索 + 分段最小上下文 + 写后沉淀回写 + 冲突显式裁决**（对齐 Rule 107）。

## 1. 问题本质
- 模型与会话上下文有限，长篇后段无法可靠记住前段细节。
- 仅依赖“紧邻前序单元/临时摘要”会丢失远距离设定（如第 30 集忘第 16 集设定）。
- 设定与大纲若只存在于计划文档或对话中，易漂移、难检索、不可追溯。

## 2. 项目级连续性资产包（事实源）
建议在项目内固定路径维护（示例，按实际项目命名调整）：

| 资产 | 路径示例 | 作用 | 维护时机 |
|---|---|---|---|
| 总纲/主大纲 (outline) | `docs/<项目>/outline.md` | 全局结构、章/集拆解、单元目标与承上启下接口、进度 | 立项创建；拆解/调整时更新；单元完成后回写进度与接口 |
| 设定/世界观圣经 (setting-bible) | `docs/<项目>/setting-bible.md` | 人物档案与状态、关系、世界观规则、时间线、硬设定/禁改项 | 立项/首单元建立；设定新增或变更时裁决并回写 |
| 知识库/事实库 (knowledge-base) | `docs/<项目>/knowledge-base.md` | 术语表、关键事实、论点与证据链/来源锚、引用约定（论文/报告尤需） | 调研与写作中持续增补；单元后沉淀 |
| 脑图/结构图 (structure-map) | `docs/<项目>/structure-map.md` 或 `.mmd` | 结构与依赖可视化：伏笔/回收、人物关系、论证链路、章节依赖 | 关键节点更新；里程碑复审时校准 |
| 连续性台账 (ledger) | 项目约定路径或 `<plan-dir>/continuity-ledger.md` | 增量流水：单元新增/变更事实、状态变化、伏笔埋设/回收、产出路径 | 每单元完成前必更新（增量，不替代上表） |

**原则**：核心设定与大纲必须有项目级落点；计划文档只登记引用与本轮增量，不作为唯一事实源。

## 3. 大纲先行与分层拆解
- **小说/剧集**：总纲（主题、主线、结局走向）→ 分卷/分集/分章骨架 → 每单元目标、冲突、状态变化与承上启下接口。
- **论文/长报告**：总论点与研究问题 → 章节提纲与各章论点 → 每节要点、证据来源与与前后章的逻辑接口。
- **门禁**：首个内容单元动笔前，必须存在并校验覆盖当前范围的总纲与拆解；缺失先补“最小可用大纲”。

## 4. 动笔前全局检索（防远距离遗忘）
每个单元开始前执行：
1. 读取总纲中本单元对应段及其前置/后置接口。
2. 检索 setting-bible / knowledge-base 中与本单元相关的实体（人物、地点、时间、术语、设定、论点、数据）。
3. 读取 continuity 台账，定位已埋伏笔、当前状态与历史变更。
4. 读取紧邻前序单元，并按台账/大纲/知识库指向读取**相关的更早单元**（禁止仅看 N）。
5. 形成“一致性检查清单”（必须遵守项/禁改项/待回收伏笔/本单元输出接口）后再写。

> 不确定即检索，不凭记忆；任务书摘要不替代原文与资产。

## 5. 分段推进与最小必要上下文（长文本优化策略）
- **单元化**：按章/集/节/论证块拆分推进，每单元有明确输入状态、目标与输出状态。
- **最小上下文包**：仅加载总纲对应段 + 相关设定/知识条目 + 必要接口/前序摘要 + 本单元要求；避免整书/整篇灌入。
- **接口显式化**：在大纲或台账记录单元间交接（人物位置与状态、时间点、悬念/伏笔、论点进度），降低跨单元依赖的隐性记忆负担。
- **长输出控制**：超长单元继续拆分子步骤；先结构后细化，保持与总纲对齐。

## 6. 单元完成后沉淀回写
- 更新 continuity 台账：本单元新增/变更事实、状态推进、伏笔埋设/回收、产出路径。
- 回写项目级资产：总纲进度与接口、setting-bible、knowledge-base、structure-map 中受影响内容。
- 做单元级一致性自检并记录遗留风险；未回写受影响资产不得宣称完成。

## 7. 冲突裁决与禁止静默覆盖
- 发现与既有设定/前文/已确立论点冲突：先标记冲突点与证据来源。
- 若为错误：修正当前单元，保持与资产一致。
- 若确需变更既有设定：**显式裁决**（原因、影响范围、替代方案），并同步回写 setting-bible/knowledge-base/outline/台账及受影响索引；必要时标注历史版本影响。
- **禁止**在后文悄悄改写早期设定或事实而不留痕、不回写。

## 8. 里程碑全局一致性审查
- 触发：完成一卷/一幕/章节组、关键转折、长篇阶段性交付前。
- 检查：人物与关系一致、时间线连续、世界观/术语/规则一致、伏笔状态一致、（论文）论点与证据链一致。
- 产出：问题清单与修复记录，回写资产与台账。

## 9. 恢复与接续
- 中断/跨会话恢复顺序：项目级资产（outline → setting-bible/knowledge-base → structure-map）→ continuity 台账 → 最近前序及当前目标相关产出。
- 资产/台账缺失或损坏：先从既有单元产出反向重建最小可用资产，再继续创作（禁凭记忆重建关键设定）。
