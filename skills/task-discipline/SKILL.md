# task-discipline — 执行纪律与工作产物维护

## 定位

管「执行过程的纪律与工作产物」——错误闭环/证据/调研/模板/反思/可靠性/能力沉淀/卫生/交互/超时/注释/来源锚/变更吸收等通用执行纪律。

## 域边界

**管**：除四文件数据流转（核心 task-planner，Rule 62）与子代理拆分/派发/调度（task-dispatch）之外的所有执行期纪律——决策前重读（Rule 4）、错误记账（Rule 6）、失败不重复（Rule 7）、新请求重规划（Rule 8/10）、错误提前暴露（Rule 9）、批量质量门控（Rule 18）、工作产物提交（Rule 27）、交互与询问门控（Rule 28）、上下文与工作文件维护（Rule 29）、错误学习闭环（Rule 31）、否决禁令追踪（Rule 32）、反思验证循环（Rule 33）、执行结论纪律（Rule 35）、技能修改保守化（Rule 36）、问题自主消解（Rule 41）、质量审查检测补充（Rule 42）、执行可靠性制度化（Rule 43）、默认项与自动超时（Rule 44）、注释完整性（Rule 45），及交付总结、根源解决、执行诚实、能力沉淀、用户指令优先、迭代测试、主动解决、周期回顾、上下文压力、裁决子代理化、呈报审批、来源锚、决策分级、变更吸收、总结审查、用户输入一致性、可测问题禁问、精准执行与极简改动等共 39 条（全文见规则索引）。

**不管**：
- 四文件内容本身（核心 task-planner，Rule 62）
- 子代理拆分/派发/并行/调度（task-dispatch）
- 媒体制作（media-planner）
