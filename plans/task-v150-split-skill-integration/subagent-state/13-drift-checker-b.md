## 二、三态判据核对

### 判据 1: 扩展与 Goal 无关联 = DRIFT

**分析**:
- Goal 核心 = 拆分模式库 + Rule 21.6 接入 + 回归零新增 FAIL + 部署位 IDENTICAL
- 用户新指令 R5 = 术语语义幻觉（实验犬误读）致定位错误
- 扩展动作 = P11 术语语义锚定 + Rule 21.6.6 术语锚定子条

**关联性判定**:
- Goal 明确包含「使 S-unit 拆分从纯数值上限升级为「数值硬门 + 模式库定性判据」双层」
- 术语语义锚定 = 「定性判据」的关键组成：若执行体连术语都理解错了，拆分模式库再完善也无法保证执行明确性
- 用户新指令明确指出「必须在执行路径和方法论上彻底规避」——扩展动作正是执行路径级机制（P11 入库 + 21.6.6 入 Rule + selftest 守护）
- **结论**: 扩展与 Goal 同域，关联性成立

### 判据 2: 扩到用户未要求范围 = DRIFT

**分析**:
- 用户要求范围 = 术语语义幻觉根治（执行路径级）
- 扩展动作范围 = task-planner 技能内部（split-pattern-library.md / critical-rules.md / selftest 脚本）
- 未涉及其他项目（如 videop1 剧本项目）
- 未涉及其他技能文件修改
- **结论**: 未越界，范围恰覆盖
