## 二、机制设计：「设计简报」供料步骤

### 2.1 承载决策（反目标自查先行）

**不新建文件**。理由（反目标「方案不得引入新的重复读取环节」）：若另立 design-brief.md，主进程要「读多份台账 → 写新文件 → 子代理再读新文件」，净增一道生成与一次读取。而 knowledge-brief 已有三处既有承载，全复用零新环节：

1. 建档：init-session 第 6 文件已自动建立（SKILL.md:64）；
2. 引用：subagent_dispatch.md:33 已规定「brief 存在时必读其索引节 §5」，check-dispatch.sh ③ 已对「brief 存在而 prompt 未引用」打告警（03 §2 D5）；
3. 契约：Rule 21.2（critical-rules.md:144）已规定 brief 计划期填写、材料包引用 §1-§5 节锚。

故「设计简报」= **一个填充步骤 + 三处格式约定**，不是新产物：把台账最小事实集按既有五段结构填进 brief，派发 prompt 按 §5 索引引用。

### 2.2 简报格式（进 knowledge-brief.md 模板填写说明，不新增 §——五段标题锚 `^## §`=5 被 selftest-knowledge-brief.sh:33 T1b 钉死）

- **§2 已验证关键事实表**：证据列新增行型「台账供料源」——每条基线定数（行数/编号/计数）优先填台账路径锚（如 `plans/.rule-reservations.jsonl:10`、`plans/task-v125/subagent-state/1-inventory.md:14-160`），其次才是原文重验锚；台账缺口维度（Rule 条款正文/模板区块结构/config 键语义）**禁止**用台账行顶替，如实填原文锚。
- **§3 关键文件锚点表**：新增行型「设计插入点+范式锚」——设计类 S-unit 必给 ① 目标文件插入点锚 ② 最新范式块锚（来源=B8 编号账本推最大 landed Rule → 文尾块行号）③ **时效戳**（供料日期+快照来源），因锚区间会漂移（B4 [sub:S3] 实证 333-357→347-371）且部署位在途写入（02 缺口⑤），过期锚须重测不得盲用。
- **§5 材料包索引表**：设计 S-unit 行的「额外材料路径」列直接填台账产物绝对路径（替代 prompt 内联）；「应读本 brief 哪节」精确到 §2/§3 行。
