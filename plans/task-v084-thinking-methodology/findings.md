```markdown
## §思维方法论（task-v084 增补 —— 解决问题前先思考问题）

> 本节落地用户思维纪律（2026-09-18）：「解决问题前先思考问题，多问几个为什么——问题是什么、本质是什么、解决方案是什么、执行方案是什么；不少于五个为什么思考法、金字塔原理，一步步推导剖析解决问题，确保后期执行不出问题、不走弯路、事半功倍」。与 §可靠性/§内容质量同构：五字段、只补位不替代、冲突以 critical-rules.md 为准。**零新开关键**：思维过程无机器判据，行为纪律+selftest 文本守护。

### T1 问题先行（Problem-First —— 解决问题前先思考问题）

- **方法名**：问题先行——任何问题进入求解前，先完成对问题本身的思考；禁止拿到任务直接动手
- **出处**：用户思维纪律（2026-09-18 指令）；Polya,《How to Solve It》(Princeton UP, 1945) 第一阶段「理解问题」（Understanding the problem）
- **触发场景**：新任务 T0 规划先行时；任何方案提出前；任何修复/改动动手前
- **可操作动作**：三问自检（答完才许进入方案设计）——①这个问题到底是什么（用自己的话复述，原话复述或等价改写）②解决到什么程度算好（可观察的验收标准）③不解决/解决错的代价是什么（爆炸半径与回滚面）；三问答案落 findings.md 或 task_plan.md 核心问题定义段
- **与既有机制映射**：宪法 §二 规划先行（复述→评估→规划→执行）的技能侧落地；Rule 4（决策前重读）；本技能 Rule 13/14（动手前路由）的前置思考层
- **失败惩罚映射**：三问未答即动手 → 按 Rule 26.3「Q2 压缩验证步骤」反向适用：回炉补三问再继续；会话内累计 ≥2 Phase → outcome 最高 PARTIAL
- **开关键**：无新增键（行为纪律+selftest-methodology 文本守护）

### T2 问题解构四问（问题是什么→本质是什么→解决方案是什么→执行方案是什么）

- **方法名**：问题解构四问——从现象到执行的四级解构链，逐级作答逐级落盘
- **出处**：用户思维纪律（2026-09-18 指令）；5 Whys = Toyota 生产系统根因分析法（大野耐一）——**与 R4/Rule 31.2 同法不同时**：31.2/R4 用于失败后错误侧归因，本条用于动手前问题侧解构，交叉引用不重复定义
- **触发场景**：计划创建时（task_plan.md「核心问题定义」段按四问作答）；方案候选提出前（D2/Rule 32.2 禁令检查同期）；复杂问题动手前
- **可操作动作**：
  1. **问题是什么**：现象、边界、影响面、验收标准（禁止把手段写成问题）
  2. **本质是什么**：连问为什么 ≥5 层（对齐 Rule 31.2 上限语义：至不可再分的根因层/本质约束）——为何存在→为何未被拦截→为何现在暴露→为何历次未根治→…；每层答案必须可追溯（T4）
  3. **解决方案是什么**：≥1 个候选方案，逐一回答「是否针对本质层」+取舍理由（含「为什么不选别的」）；候选先过 Rule 32.2 禁令检查
  4. **执行方案是什么**：步骤化（S-unit 化）、每步可验证（三证据）、门控点与兜底（衔接 R2 FMEA 预演）
  - 四问答案落 task_plan.md「核心问题定义」+ findings.md；skip 任何一问 = 计划未定稿
- **与既有机制映射**：Rule 31.2（错误侧 5 Whys，同法不同时）；Rule 32.2（候选禁令检查）；Rule 22.6/21.1b（执行方案步骤化即 S-unit 表）；task_plan.md「核心问题定义」段=落盘载体
- **失败惩罚映射**：四问缺答（尤其②本质层被跳过）即定方案 → Rule 26.3「Q2 压缩验证步骤」：回炉补解构；会话内累计 ≥2 → 最高 PARTIAL
- **开关键**：无新增键

### T3 金字塔原理（结论先行、以上统下、归类分组、逻辑递进）

- **方法名**：金字塔原理（Pyramid Principle）——结论先行/以上统下/归类分组/逻辑递进四律
- **出处**：Barbara Minto,《The Pyramid Principle: Logic in Writing and Thinking》(Minto International, 1987；源自麦肯锡)
- **触发场景**：方案陈述、D2/AskUserQuestion 选项呈现、计划文档与交付报告组织、28.2.1 思路复述
- **可操作动作**：①结论先行：先给判断/推荐再给论据，禁先铺背景再说结论；②以上统下：上层观点必须是下层论据的概括；③归类分组：同层论据 MECE（相互独立、完全穷尽）；④逻辑递进：同层按时间/重要性/结构序排列。选项呈现＝①的实例：Recommended 项排首位并给理由（宪法 §四 同构）
- **与既有机制映射**：宪法 §四 选项呈现规范；Rule 28.2.1（≤5 行思路复述=结论先化的压缩形态）；Rule 19.6（task_plan 瘦身指针制=以上统下的文档形态）
- **失败惩罚映射**：**显式例外（不进 Rule 26.3 硬门）**——写作风格类无客观判据，硬门会伪报；降为提醒级：终验 Evidence 抽查发现报告/方案违反①②④ → 记待改项并复述给用户，不阻断交付
- **开关键**：无新增键

### T4 逐步推导剖析（每步推导可追溯，禁跳步）

- **方法名**：逐步推导剖析——结论必须能从前提一步步走到；跳步=未验证假设
- **出处**：用户思维纪律（2026-09-18 指令）；形式逻辑论证链（前提→推理→结论）；MECE（Minto 金字塔姊妹法）
- **触发场景**：T2 第②③级作答时；R2 FMEA 失败模式推演；Rule 31.2 根因分析；复杂调试与排查
- **可操作动作**：推导链显式化并落 findings.md：「前提 A + 观察 B →（推理规则）→ 中间结论 C → … → 最终结论」；推导断点=待验证假设，显式标注「未验证」并登记验证动作（对齐宪法 §三 无第一手证据结论须标未验证）；禁止循环论证（用结论反推前提）
- **与既有机制映射**：Rule 3（双操作落盘）→ 推导链落 findings；R4 5 Whys=推导链的纵向追问形态；Rule 6（错误留痕）
- **失败惩罚映射**：关键结论无推导链/跳步未标 → Rule 26.3「Q3 证据不实」轻档：补链后再继续；伪造推导链（结论先行反装推导）→ Q3 最高档 BLOCKED + STOP
- **开关键**：无新增键

### T5 消费点与联动（何时必须用）

- **方法名**：思维方法论消费点（触发时机汇总）
- **出处**：task-v084 落地设计（挂载既有流程节点，不新建门控）
- **触发场景**：（本条即触发时机清单）
- **可操作动作**：五个消费点——①T0 规划先行：复述指令后、动手前跑 T1 三问；②计划创建：task_plan.md「核心问题定义」段按 T2 四问作答（plan-writer 产出契约行承接）；③方案候选/D2 选项前：T2③ 解法层 + T3 结论先行 + Rule 32.2 禁令检查；④Phase 执行前：Poka-Yoke 检查点同期并读本节（SKILL.md Poka-Yoke 行指针）；⑤失败/纠偏时：Rule 31.2（错误侧）+T4 推导链复盘

- **开关键**：无新增键
```
