**git 使用加强协议（P0）**：
- **101.0 总纲（两侧义务，定义）**：加强 git 使用=**起点侧**任务开始固定原始数据（101.1）+**终点侧**处理完成后主动合并 worktree 并解决所有冲突（101.2）。「主动」=不等用户指令，任务收口时合并/解冲突是收口动作本身（Rule 95 执行优先同原理）；「固定」=把任务范围内的原始文件状态提交进 git 历史，给任务回滚点。
- **101.1 起点侧（固定原始数据提交，Rule 90 首提交普适化）**：一切实现类任务（**含 L0-T 文本档/mini 档**）开工前，用 git 固定任务范围内文件的当前状态——范围内文件有未提交脏态=先提交固定（提交信息注明 `baseline(<task-id>): 固定任务前原始数据`，Rule 90 首提交同构）再动手；范围内文件干净=免提交（干净态即固定点，Decisions Made/progress 记一行 baseline=HEAD commit 号）。**范围外脏态禁代落**（Rule 88 射程/宪法 §四.1 写入最小化）：只按 Rule 70 呈报清单（路径+改动性质），按用户裁决处置，禁把范围外变更捎带进 baseline 提交（判例=位仓 `add skills/` 捎带杂物，须 pathspec 收窄）。worktree 开发任务：本条提交位=worktree 内部（worktree 自 HEAD 基线，主仓 .gitignore 忽略 `tmp/worktrees/` 路径不影响 worktree 内部 git 管理，100.3② 同口径）。
- **101.2 终点侧（主动合并+解决所有冲突）**：处理完成后（全 VC 复验过）**主动**执行 worktree→主分支合并（`smart-merge-back.sh <worktree-path>`，不等用户指令，95 执行优先）；**冲突=收口义务**：逐条走 41.1 消解链（①git 三方合并/并集解 ②手动解冲突→复验 ③分叉重基），「解决所有冲突」=merge 冲突清零**且**解后 VC 复验过才进入收口（清理 worktree+分支→簿记→交付）；**真门（95.5）=消解配额耗尽仍冲突**（41.1 三路径全败+冲突语义不可并集判断）才 STOP 报告用户（Rule 70 四要素+冲突 hunk 看点）并在 progress 登记 `[conflict-unresolved]`；**冲突禁留交付态**（冲突标记残留=任务未完成，§三「应该没问题」禁用）。**不乱解守卫保留**：解冲突必带复验（VC/selftest/Read 对照）——无复验的解=假收口（Rule 54 执行诚实）；并集解仅限两侧增量场景（双方新增/双方改而语义兼容），判为语义冲突处必须手动解+复验，禁并集掩盖。
